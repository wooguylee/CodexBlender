# 로컬 Blender 제어 설계

사용자 승인: 2026-09-09, 권장안(Blender 작업 창 + 대화의 미리보기)을 구현하고 모든 자료를 현재 프로젝트에 저장한다. 다른 PC에서 Git clone 후 재사용하고 AGENTS.md로 후속 작업 절차를 관리한다.

## 구조

- Python 표준 라이브러리와 Blender 내장 bpy만 사용한다. 네트워크 서버, 계정, 외부 모델 서비스는 필요하지 않다.
- CLI가 프로젝트의 `.runtime/`에 세션별 명령 파일을 원자적으로 기록한다. 새로 연 Blender가 메인 스레드의 타이머에서 순서대로 처리한다.
- OS 파일 잠금으로 한 프로젝트의 연결을 하나로 제한한다. 재실행 시 새 세션을 사용하여 이전 명령을 재실행하지 않는다.
- `run`은 프로젝트 안 Python 파일을 작업 폴더에 복사하여 실행한다. 실행 전 장면 백업, 실행 후 현재 장면과 작업별 사본 저장, PNG 미리보기가 기본이다.
- 스크립트 오류 시 부분 변경이 남을 수 있다. 실패 내용을 기록하고 자동 재시도하지 않는다. 백업 복구는 명시적인 파일 열기로 수행한다.
- 연결 종료는 타이머만 정지하며 Blender 창은 남긴다. 기존에 실행 중인 다른 Blender 창을 건드리지 않는다.

## 저장과 이식

- 도구: `bridge/`, `scripts/`. 사용자 작업 코드: `workflows/`. 원본: `scenes/`, `assets/`. 결과·코드 사본·이력: `outputs/`.
- 실행 경로는 저장소 위치에서 계산한다. 머신별 Blender 경로는 환경변수 `BLENDER_EXECUTABLE` 또는 Git 제외 파일 `blender.local.json`에만 둔다.
- `.runtime/`, Python 캐시, Blender 임시 백업은 Git에서 제외한다. 의도적인 `.blend` 백업과 PNG, 작업 결과는 기본적으로 보존한다.
- Windows PowerShell 실행기는 Blender 내장 Python을 찾는다. Python 3.11+ CLI는 Windows/macOS/Linux 경로 검색을 제공하되 실제 검증한 OS만 검증 보고서에 명시한다.

## 작업 통제

AGENTS.md는 에이전트 행동 지침이며 OS 보안 샌드박스가 아니다. Python은 사용자 계정 권한으로 실행된다. 프로젝트 경계 검사는 도구의 파일 인수에 적용하며 임의 Python의 모든 파일 접근을 제한하지 않는다. 신뢰하는 프로젝트 코드만 실행한다.

## 수락 기준

Blender 실행 경로 탐색, 새 작업 창 연결, 중복 실행 방지, 상태/장면 조회, 예제 생성, 색/크기 수정, 백업/저장/미리보기, 오류 응답과 이후 정상 명령, 재시작 복원, 복제한 경로에서 실행을 검증한다. 타 PC의 GPU/OS 자체는 이 PC에서 검증했다고 주장하지 않는다.
