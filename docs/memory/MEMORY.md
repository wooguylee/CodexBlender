# 프로젝트 메모리

사용자가 명시적으로 기억하도록 요청한 명칭·선호·작업 규칙을 보관한다. 이 파일은 Git으로 공유하며 다른 PC의 Codex도 세션 시작 시 읽는다. 현재 장면과 진행 상태는 `../current-state.md`에서 별도로 관리한다.

## 모든 작업의 마무리는 Git 커밋·푸시

사용자 지시일: 2026-10-02.

사용자 원문: **“깃 커밋/푸시를 하라는 의미야. 모든 작업의 마무리는 깃 커밋/푸시!!”**

- 승인된 작업은 구현·검증·관련 변경 커밋·원격 푸시·원격 반영 확인까지 완료한다.
- 커밋/푸시 요청을 매번 따로 기다리지 않는다. 문서와 지침만 수정한 작업도 동일하다.
- 로컬 HEAD와 원격 브랜치 해시를 비교하고 커밋/푸시 결과를 사용자에게 보고한다.
- 무관한 기존 변경, 비밀정보, 머신 설정은 함께 올리지 않는다. 강제 푸시나 원격 이력 덮어쓰기를 허용하는 규칙은 아니다.
- 기존의 “Git 커밋/푸시는 별도 요청 범위에서만”이라는 해석을 이 상시 지시로 대체한다. 사용자가 해당 작업에서 명시적으로 금지하면 그 지시가 우선한다.
- 실행 지침은 루트 `AGENTS.md`의 “작업 마무리: Git 커밋·푸시”에 반영한다.

## 메모리는 Codex와 프로젝트에 함께 기록

사용자 지시일: 2026-09-10.

- 사용자가 “메모리해”, “기억해 둬”라고 요청하면 **Codex 메모리와 현재 프로젝트의 메모리 영역 양쪽에 기록**한다. Codex 메모리에만 저장하고 완료로 처리하지 않는다.
- 이 프로젝트의 메모리 기준 파일은 `docs/memory/MEMORY.md`다. 다른 프로젝트에서는 해당 프로젝트의 기존 메모리 영역을 먼저 확인하고, 없으면 문서 구조에 맞는 메모리 파일을 만든다.
- 후속 에이전트가 지켜야 할 실행 규칙은 `AGENTS.md`에도 반영하거나 이 파일을 필수로 읽도록 연결한다.
- 프로젝트 기록에는 다른 PC에서 이해하고 실행하는 데 필요한 배경, 명칭의 의미, 적용 절차를 담는다. PC별 절대 경로, 비밀키, 일시적인 연결 상태에 의존하지 않는다.
- 완료 보고에는 양쪽 기록 여부와 프로젝트 파일 경로를 밝힌다. Git 원격 반영 여부는 실제 확인된 상태로 구분한다. 다른 PC에는 커밋·푸시 후 clone/pull로 전달된다.

## 브리찌

사용자 명명일: 2026-09-10.

**브리찌**는 이 프로젝트의 **Codex–Blender 로컬 제어 브리지**를 뜻한다. Blender Python API(`bpy`), 프로젝트 내부 파일 큐 IPC, Blender 타이머(`bpy.app.timers`)를 사용한다.

사용자가 “브리찌로 컵을 만들어줘”, “브리찌를 이용해서 색을 바꿔줘”라고 지시하면 이 도구를 통한 Blender 작업 요청으로 해석한다.

1. `AGENTS.md`, `README.md`, 이 메모리와 `docs/current-state.md`를 확인한다.
2. 실제 프로젝트 루트에서 `scripts/blender.ps1 status`로 연결을 확인하고 필요하면 `start`한다. `scene`으로 현재 장면을 조회한다.
3. 승인된 요청 범위의 제작 코드를 `workflows/`에 저장하고 `run --script ...`로 실행한다.
4. 변경 전 백업, 원본 저장, 미리보기 확인과 프로젝트 내 결과 보존 규칙을 따른다. 사용자에게 중간 결과를 보여준다.

이미 승인된 작업은 반복 확인 없이 진행한다. 명칭 지정만으로 무관한 삭제·외부 업로드 등까지 허용되는 것은 아니다. 브리찌는 MCP나 마우스 자동화의 별칭이 아니다.
